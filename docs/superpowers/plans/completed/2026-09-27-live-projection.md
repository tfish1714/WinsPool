# Results-Aware Season Projection (Daily) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** The daily prediction job must produce a NEW per-team total-wins projection for the current season that takes the games already played into account (wins to date plus a fresh simulation of the rest of the season with ratings updated by the real results), stored separately from the frozen preseason numbers, so the preseason set stays intact for draft analytics (good picks, surprises) while a current projection is available all season and its week-by-week trend is kept.

**Architecture:** `NNProjectionEngine.simulate_season(schedule, n_sims, completed_results)` already applies real margins deterministically (updating Elo/EPA) and simulates the rest; `get_team_win_projections` simply never passes `completed_results`, so `scripts/cache_builder.py` re-simulates all 17 games from the preseason state every day (fixed seed 42, identical output). The change: (1) wire completed results in; (2) write the result to a new collection `season_projections` (current, overwritten daily) plus `season_projection_history` (one doc per team per completed week, kept); (3) stop rewriting `preseason_predictions` once the season's DRAFT IS COMPLETE and lock it (before the draft completes the daily job keeps refreshing it as today; the frozen `draft_snapshot_predictions` continues to be the pre-draft fairness baseline); (4) mirror both collections locally; (5) expose the current projection on the read path and the team page / player page.

**Tech Stack:** Python, numpy, pandas, Firestore (google-cloud-firestore), FastAPI, vanilla JS, pytest.

## Review Focus

- Ties: `simulate_season` credits `not home_won` to the away team when `real_margin == 0`, so a completed tie would wrongly give the away team a win. A tie must credit neither team a win (pool counts wins only) while still updating ratings with margin 0.
- Completed results must come from the games table's `result` column (home margin) for REG games of the season only; a game with null `result` or the sentinel -1000 is NOT completed; keys must match `W{week:02d}_{home}_{away}` with NORMALIZED abbreviations exactly as `simulate_season` builds them (it normalizes team codes).
- The projection for an in-progress season must equal wins to date plus simulated remainder: for a team with all games completed, `projected_wins == actual wins`, `std_dev == 0`; a test must prove a completed week changes the projection relative to the no-results run (regression test for the original bug).
- `preseason_predictions` for a season whose draft is complete must never be overwritten by the daily job; only locked (idempotent). While the draft is not complete the current behavior (daily refresh, unlocked) remains for that season and for next season's early projections. `draft_is_complete(season)`: the season's `draft_results` row count is at least the total number of picks defined for that season (from `draft_order_rules`: sum of the pick columns per rule row, or the number of `draft_order` rows x 3 when rules are absent; fall back to 30) AND at least one pick exists; put this in one small tested helper (for example `services/draft_state.py::draft_is_complete(season, draft_results, draft_order, draft_order_rules)`), reuse it anywhere else that needs the same notion, and keep it independent of the `draft_active` flag (the flag can be toggled off mid-draft).
- Idempotence and safety: rerunning the job the same day rewrites identical current docs; history docs are keyed `{season}_w{week:02d}_{team}` so reruns overwrite the same doc, never duplicate; a failed write for one collection must not stop the other collections or crash the job (existing try/except pattern), but must be logged.
- Cost: the daily job has a fixed runtime budget (~4 min); do not add a second full simulation: reuse the single `get_team_win_projections` call for both `season_projections` and history.
- Season completion: after week 18, current projections equal actual final wins with `locked=True`.
- Local mirror parity: refresh_local_pkls writes `season_projections` and `season_projection_history` in the format the readers expect (pkl + per-year slices, like preseason_predictions).
